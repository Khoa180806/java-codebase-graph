# Learning log — 2026-11-05
**Task:** P1-T3  ·  **Chế độ:** LEARN  ·  **Thời gian:** 1.5h

## 1. Hôm nay em làm gì (2-3 dòng)

- Hoàn thành thiết kế và cài đặt class `JavaCodeParser` sử dụng JavaParser 3.28.2 hỗ trợ phân tích mã nguồn Java 21.
- Triển khai kỹ thuật Constructor Chaining (`this(...)`) để mặc định thiết lập `LanguageLevel.JAVA_21` và đồng thời cho phép mở rộng cấu hình `ParserConfiguration` từ bên ngoài.
- Viết bộ unit test `JavaCodeParserTest` sử dụng Text Blocks `"""..."""` và `@TempDir`, kiểm thử parse chuỗi Java 21 hợp lệ (`record`), chuỗi lỗi cú pháp (fault-tolerant, không làm crash tiến trình), và parse từ file `Path` thật. Toàn bộ 12/12 unit tests trong dự án đều pass xanh.

## 2. Giải thích bằng lời của mình *(Khoa tự viết, không copy từ AI)*

- Trong một công cụ static analysis, việc một file bị lỗi cú pháp là điều bình thường. Thay vì để ném `ParseProblemException` làm sập toàn bộ hệ thống, việc dùng `JavaParser` instance trả về `ParseResult<CompilationUnit>` giúp gom toàn bộ lỗi vào `List<Problem>` một cách an toàn mà không làm sập chương trình.
- Áp dụng kỹ thuật Constructor Chaining giúp tái sử dụng logic khởi tạo, tuân thủ nguyên lý DRY (Don't Repeat Yourself).
- Kiểm tra `result.isSuccessful()` trước khi truy xuất AST node từ `Optional<CompilationUnit>` là bắt buộc để tránh ngoại lệ `NoSuchElementException`.

## 3. Em đã vấp ở đâu / lỗi gì / sửa thế nào

- Ban đầu chỉ viết một constructor nhận `ParserConfiguration`, khiến việc khởi tạo sử dụng ở các nơi khác bị cồng kềnh. Sau khi được Mentor gợi ý, đã bổ sung thêm no-arg constructor tự động cấu hình Java 21 bằng cú pháp `this(...)`.
