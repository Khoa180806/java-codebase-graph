# v1.1 — Incremental Re-index & File Watcher

## Vấn đề
v1.0 phải restart server mỗi khi sửa code (ADR-005). Với dự án lớn, re-index toàn bộ chậm và phiền.

## Mục tiêu
Sửa/thêm/xoá file `.java` → graph cập nhật chỉ cho phần bị ảnh hưởng, không cần restart.

## Phạm vi
- Theo dõi thay đổi bằng `WatchService` (hoặc tool `reindex` thủ công trước, watcher sau).
- Khi file đổi: xoá node/cạnh **sinh ra từ file đó**, parse lại, thêm lại; cạnh từ file khác trỏ vào vẫn đúng.
- Graph chuyển từ immutable-sau-build sang **snapshot swap**: build graph mới rồi thay tham chiếu atomic (`AtomicReference`/`volatile`) — truy vấn đang chạy không thấy trạng thái nửa vời.

## Acceptance

- Test chứng minh truy vấn đồng thời với reindex không lỗi/không đọc dữ liệu nửa vời.

## Rủi ro
Cạnh từ file A trỏ vào type ở file B: khi B đổi signature, cạnh của A cần re-resolve → quyết định chiến lược (re-resolve file phụ thuộc, hoặc đánh dấu stale).

## Khái niệm học được
Concurrency cơ bản, visibility (`volatile`), snapshot isolation, debounce, `java.nio.file.WatchService`.
